# Первый эксперимент

## 1. Что исследуем и почему это важно

Исследуем, как объективная доказательная сила данных и заранее заданный ошибочный prior влияют на выбор языковой модели между двумя физическими гипотезами. Эксперимент нужен для проверки основного исследовательского вопроса: пересматривает ли модель ошибочное исходное убеждение по мере усиления данных и насколько её поведение отличается от ожидаемого статистического решения.

Первый эксперимент не разделяет извлечение свидетельства из чисел и его интеграцию с prior: модель одновременно получает исходные наблюдения и рассчитанные статистические характеристики. Поэтому дополнительный исследовательский вопрос в этом запуске отдельно не проверяется.

## 2. Физическая система и гипотезы

В эксперимент включены данные, в которых истинной является \(H_1\):

`H1: f(x) = kx + alpha*x^3`

И данные, в которых истинной является \(H_0\):

`H0: f(x) = kx`

В данных используется \(k=1\), к истинной зависимости добавляется нормальный шум. Сила свидетельства в пользу \(H_1\) меняется за счёт диапазона наблюдений, уровня шума и выраженности кубического члена. Наборы с истинной \(H_0\) используются как отрицательные контроли для измерения ложного выбора \(H_1\).

## 3. Данные

Для калибровки используется фиксированная сетка:
1. `X`: 1, 2, 4, 6, 8, 10;
2. `r`: от 0.05 до 1.00, 11 значений;
3. `s`: от 0.01 до 0.40, 9 значений;
4. Число наблюдений в одном наборе: 50;
5. Число Monte Carlo повторов на одну комбинацию параметров: 1000.

Для каждой комбинации отдельно оцениваются вероятность того, что данные, порождённые \(H_1\), поддерживают \(H_1\), и вероятность того, что данные, порождённые \(H_0\), поддерживают \(H_0\). Режимы выбираются только по H1 для 12 целевых уровней: 0.50, 0.55, 0.60, 0.65, 0.70, 0.75, 0.80, 0.85, 0.90, 0.95, 0.99 и 1.00. Для H0 целевой уровень не задаётся, а фактическая \(P(Delta BIC<0\mid H_0)\) сохраняется только как дополнительная диагностическая метрика для режима, выбранного по H1.

Основной набор v4 содержит 50 реализаций с истинной \(H_0\) и 50 реализаций с истинной \(H_1\) для каждого режима, всего 1200 наборов данных. Для каждого набора сохраняются:
1. Массивы `x` и `y`;
2. Параметры генерации;
3. SSE для \(H_0\) и \(H_1\);
4. BIC для \(H_0\) и \(H_1\), а также Delta BIC;
5. Логарифмы правдоподобия и `log_likelihood_ratio = logL1 - logL0`;
6. Истинная гипотеза;
7. Target и calibrated evidence strength для H1, а для H0 — фактическую evidence strength без target;
8. Ожидаемая вероятность и ожидаемый выбор гипотезы с учётом prior.

Сетка генерации данных не менялась. В v2 был исправлен способ задания seed, в v3 введены истинная \(H_0\) и контрбалансировка порядка гипотез. В v4 отдельно калибруется доказательная сила H0 и из System Prompt удалён фиксированный порядок описания гипотез. Старые данные v1 не используются для итоговой интерпретации, поскольку содержат повторяющиеся реализации.

## 4. Схема и дизайн эксперимента

Независимые факторы:
1. Доказательная сила: 12 уровней;
2. Prior: neutral и wrong;
3. Истинная гипотеза: H0 и H1;
4. Порядок предъявления: H0/H1 и H1/H0;
5. Модель: Qwen3-0.6B и Qwen3-4B-AWQ.

Условия prior:
1. `neutral`: P(H0) = 0.50, P(H1) = 0.50;
2. `wrong` при истинной H0: P(H0) = 0.10, P(H1) = 0.90;
3. `wrong` при истинной H1: P(H0) = 0.90, P(H1) = 0.10.

Один и тот же набор данных используется для обоих prior и обеих моделей. Это позволяет сравнивать условия на одинаковых реализациях шума. Порядок гипотез распределяется поровну внутри каждой комбинации режима и истинной гипотезы: 25 наборов используют H0/H1 и 25 — H1/H0. История между испытаниями отсутствует, каждый запрос выполняется независимо.

Объём эксперимента:
1. 1200 наборов данных;
2. 2 условия prior;
3. 2400 испытаний на одну модель;
4. 4800 испытаний для двух моделей.

В одном испытании модель получает описания \(H_0\) и \(H_1\) в одном из двух порядков, численные значения prior, исходные наблюдения и рассчитанные метрики. Допустимый итоговый ответ — только `H0` или `H1`; уверенность модели отдельно не запрашивается.

## 5. Модели и конфигурации

### Qwen3-0.6B

Базовая компактная модель. Используется для проверки полного контура эксперимента и как нижняя точка сравнения.

1. Конфигурация: `configs/ex1_qwen3_06b_v4.yaml`;
2. Сервер: `compose.yaml`;
3. Максимальная длина контекста: 8192 токенов;
4. Зафиксированная revision: `c1899de289a04d12100db370d81485cdf75e47ca`.

### Qwen3-4B-AWQ

Более мощная модель в 4-битной AWQ-квантизации. Она выбрана как практически доступная для ASUS TUF Gaming F16 с RTX 3050 6 GB.

1. Конфигурация: `configs/ex1_qwen3_4b_awq_v4.yaml`;
2. Сервер: `compose.qwen3-4b-awq.yaml`;
3. Максимальная длина контекста: 4096 токенов;
4. GPU memory utilization: 0.80;
5. Используется eager mode;
6. Зафиксированная revision: `74d4bd2bd4bff9cafc9345221320bffb08b406a3`.

Общие параметры ответа: temperature = 0, top_p = 0.8, top_k = 20, max_tokens = 512, thinking выключен, seed = 42. Архитектура моделей, физические законы и сетка параметров генерации не менялись.

## 6. Что сохраняется после запуска

Для каждого запуска создаётся отдельная директория в `outputs/runs/`, содержащая:
1. `responses.jsonl` — ответы модели, условия и связанные данные;
2. `failures.jsonl` — ошибки отдельных испытаний;
3. `resolver_config.yaml` — итоговая конфигурация запуска;
4. `manifest.json` — сведения о запуске и входных файлах;
5. `metrics.json` — агрегированные результаты.

В `metrics.json` сохраняются planned, completed, successful, failed и invalid trials, accuracy, balanced accuracy, true positive rate, false positive rate, false negative rate, true negative rate, доля выбора \(H_1\), Wilson 95% CI и совпадение с ожидаемым выбором. Отдельные разрезы строятся по prior, истинной гипотезе, порядку предъявления и уровням доказательной силы для обеих истинных гипотез.

## 7. Гипотезы и ожидаемые результаты

1. Вероятность правильного выбора \(H_1\) увеличивается с ростом доказательной силы;
2. Wrong prior снижает точность как при истинной \(H_0\), так и при истинной \(H_1\);
3. Различие между prior уменьшается на высоких уровнях доказательной силы;
4. Порядок H0/H1 и H1/H0 не должен существенно менять точность; отклонение будет интерпретироваться как позиционное смещение;
5. Qwen3-4B-AWQ показывает более устойчивую зависимость от силы данных и меньшую частоту ложных срабатываний, чем Qwen3-0.6B;
6. На слабых и средних уровнях доказательной силы расхождение с ожидаемым статистическим выбором будет выше, чем на сильных.

## 8. На что смотреть после запуска

1. Все ли 2400 испытаний завершились для каждой модели;
2. Есть ли ошибки API, невалидные или неразобранные ответы;
3. Как меняется доля правильного выбора \(H_1\) по 12 уровням доказательной силы;
4. Каковы false positive rate на данных \(H_0\) и false negative rate на данных \(H_1\);
5. Насколько различаются neutral и wrong prior на одинаковых данных;
6. Различаются ли результаты при порядке H0/H1 и H1/H0;
7. Монотонна ли зависимость и где появляются локальные отклонения;
8. Перекрываются ли 95% доверительные интервалы двух prior и двух моделей;
9. Насколько фактический выбор совпадает с ожидаемым выбором по prior и Delta BIC;
10. Есть ли систематическое преимущество Qwen3-4B-AWQ над Qwen3-0.6B;
11. Не определяются ли результаты отдельными уровнями, режимами генерации или техническими ошибками.

## 9. Текущий статус

Полные диагностические запуски v3 выполнены для обеих моделей и выявили почти постоянный выбор H1. В v4 из System Prompt удалено фиксированное перечисление гипотез, а для H0 добавлена отдельная Monte Carlo-оценка. Набор v4 создан и проверен: 1200 уникальных наборов и seed, по 600 для H0 и H1. Режимы выбраны только по target H1; для H0 target не задаётся, а evidence strength сохраняется как диагностическая метрика. Полные запуски моделей v4 ещё не выполнены.

## 10. Запуск

Qwen3-0.6B:

```powershell
docker compose up -d
poetry run python scripts/run_experiment.py configs/ex1_qwen3_06b_v4.yaml
docker compose stop
```

Qwen3-4B-AWQ:

```powershell
docker compose -f compose.qwen3-4b-awq.yaml up -d
poetry run python scripts/run_experiment.py configs/ex1_qwen3_4b_awq_v4.yaml
docker compose -f compose.qwen3-4b-awq.yaml stop
```
