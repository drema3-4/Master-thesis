# Первый эксперимент

## 1. Что исследуем и почему это важно

Исследуем, как объективная доказательная сила данных и заранее заданный ошибочный prior влияют на выбор языковой модели между двумя физическими гипотезами. Эксперимент нужен для проверки основного исследовательского вопроса: пересматривает ли модель ошибочное исходное убеждение по мере усиления данных и насколько её поведение отличается от ожидаемого статистического решения.

Первый эксперимент не разделяет извлечение свидетельства из чисел и его интеграцию с prior: модель одновременно получает исходные наблюдения и рассчитанные статистические характеристики. Поэтому дополнительный исследовательский вопрос в этом запуске отдельно не проверяется.

## 2. Физическая система и гипотезы

Истинной во всех испытаниях является гипотеза \(H_1\):

`H1: f(x) = kx + alpha*x^3`

Конкурирующая упрощённая гипотеза:

`H0: f(x) = kx`

В данных используется \(k=1\), к истинной зависимости добавляется нормальный шум. Сила свидетельства в пользу \(H_1\) меняется за счёт диапазона наблюдений, уровня шума и выраженности кубического члена.

## 3. Данные

Для калибровки используется фиксированная сетка:
1. `X`: 1, 2, 4, 6, 8, 10;
2. `r`: от 0.05 до 1.00, 11 значений;
3. `s`: от 0.01 до 0.40, 9 значений;
4. Число наблюдений в одном наборе: 50;
5. Число Monte Carlo повторов на одну комбинацию параметров: 1000.

Для каждой комбинации оценивается вероятность того, что данные поддерживают истинную гипотезу. После калибровки выбираются режимы для 12 целевых уровней доказательной силы: 0.50, 0.55, 0.60, 0.65, 0.70, 0.75, 0.80, 0.85, 0.90, 0.95, 0.99 и 1.00.

По конфигурации основной набор v2 будет содержать 100 независимых реализаций для каждого уровня, всего 1200 наборов данных. Для каждого набора сохраняются:
1. Массивы `x` и `y`;
2. Параметры генерации;
3. SSE для \(H_0\) и \(H_1\);
4. BIC для \(H_0\) и \(H_1\), а также Delta BIC;
5. Логарифмы правдоподобия и `log_likelihood_ratio = logL1 - logL0`;
6. Ожидаемая вероятность и ожидаемый выбор гипотезы с учётом prior.

Сетка генерации данных не менялась. В v2 изменён только способ задания seed, чтобы 100 реализаций внутри одного уровня действительно были независимыми. Старые данные v1 не используются для итоговой интерпретации, поскольку содержат повторяющиеся реализации.

## 4. Схема и дизайн эксперимента

Независимые факторы:
1. Доказательная сила: 12 уровней;
2. Prior: neutral и wrong;
3. Модель: Qwen3-0.6B и Qwen3-4B-AWQ.

Условия prior:
1. `neutral`: P(H0) = 0.50, P(H1) = 0.50;
2. `wrong`: P(H0) = 0.90, P(H1) = 0.10.

Один и тот же набор данных используется для обоих prior и обеих моделей. Это позволяет сравнивать условия на одинаковых реализациях шума. История между испытаниями отсутствует, каждый запрос выполняется независимо.

Объём эксперимента:
1. 1200 наборов данных;
2. 2 условия prior;
3. 2400 испытаний на одну модель;
4. 4800 испытаний для двух моделей.

В одном испытании модель получает описание \(H_0\) и \(H_1\), численные значения prior, исходные наблюдения и рассчитанные метрики. Допустимый итоговый ответ — только `H0` или `H1`; уверенность модели отдельно не запрашивается.

## 5. Модели и конфигурации

### Qwen3-0.6B

Базовая компактная модель. Используется для проверки полного контура эксперимента и как нижняя точка сравнения.

1. Конфигурация: `configs/ex1_qwen3_06b_v2.yaml`;
2. Сервер: `compose.yaml`;
3. Максимальная длина контекста: 8192 токенов;
4. Зафиксированная revision: `c1899de289a04d12100db370d81485cdf75e47ca`.

### Qwen3-4B-AWQ

Более мощная модель в 4-битной AWQ-квантизации. Она выбрана как практически доступная для ASUS TUF Gaming F16 с RTX 3050 6 GB.

1. Конфигурация: `configs/ex1_qwen3_4b_awq_v2.yaml`;
2. Сервер: `compose.qwen3-4b-awq.yaml`;
3. Максимальная длина контекста: 4096 токенов;
4. GPU memory utilization: 0.80;
5. Используется eager mode;
6. Зафиксированная revision: `74d4bd2bd4bff9cafc9345221320bffb08b406a3`.

Общие параметры ответа: temperature = 0, top_p = 0.8, top_k = 20, max_tokens = 512, thinking выключен, seed = 42. Архитектура моделей и логика генерации данных в рамках подготовки эксперимента не менялись.

## 6. Что сохраняется после запуска

Для каждого запуска создаётся отдельная директория в `outputs/runs/`, содержащая:
1. `responses.jsonl` — ответы модели, условия и связанные данные;
2. `failures.jsonl` — ошибки отдельных испытаний;
3. `resolver_config.yaml` — итоговая конфигурация запуска;
4. `manifest.json` — сведения о запуске и входных файлах;
5. `metrics.json` — агрегированные результаты.

В `metrics.json` сохраняются planned, completed, successful, failed и invalid trials, доля выбора \(H_1\) по prior, Wilson 95% CI, совпадение с ожидаемым выбором и результаты по каждому уровню доказательной силы.

## 7. Гипотезы и ожидаемые результаты

1. Вероятность выбора \(H_1\) увеличивается с ростом доказательной силы;
2. При wrong prior модель реже выбирает \(H_1\), чем при neutral prior;
3. Различие между prior уменьшается на высоких уровнях доказательной силы;
4. Qwen3-4B-AWQ показывает более устойчивую и монотонную зависимость от силы данных, чем Qwen3-0.6B;
5. На слабых и средних уровнях доказательной силы расхождение с ожидаемым статистическим выбором будет выше, чем на сильных.

## 8. На что смотреть после запуска

1. Все ли 2400 испытаний завершились для каждой модели;
2. Есть ли ошибки API, невалидные или неразобранные ответы;
3. Как меняется доля выбора \(H_1\) по 12 уровням доказательной силы;
4. Насколько различаются neutral и wrong prior на одинаковых данных;
5. Монотонна ли зависимость и где появляются локальные отклонения;
6. Перекрываются ли 95% доверительные интервалы двух prior и двух моделей;
7. Насколько фактический выбор совпадает с ожидаемым выбором по prior и Delta BIC;
8. Есть ли систематическое преимущество Qwen3-4B-AWQ над Qwen3-0.6B;
9. Не определяются ли результаты отдельными уровнями, режимами генерации или техническими ошибками.

## 9. Текущий статус

Код полного цикла, конфигурации v2 и запуск обеих моделей проверены. Qwen3-0.6B и Qwen3-4B-AWQ отвечают через локальный API на используемом оборудовании. Основной набор данных v2 ещё не создан, полный эксперимент ещё не выполнен, итоговые графики и выводы отсутствуют. Они должны строиться только по новым запускам v2.

## 10. Запуск

Qwen3-0.6B:

```powershell
docker compose up -d
poetry run python scripts/run_experiment.py configs/ex1_qwen3_06b_v2.yaml
docker compose stop
```

Qwen3-4B-AWQ:

```powershell
docker compose -f compose.qwen3-4b-awq.yaml up -d
poetry run python scripts/run_experiment.py configs/ex1_qwen3_4b_awq_v2.yaml
docker compose -f compose.qwen3-4b-awq.yaml stop
```
